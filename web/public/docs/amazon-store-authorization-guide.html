AMAZON SP-API

店铺授权详细文档

本文档用于说明当前系统“店铺管理”页面的 Amazon SP-API 店铺授权流程、必备配置、字段含义、测试校验方式和常见故障排查。 文档内容基于当前项目代码实现整理，可直接交给运营、实施、开发或运维人员使用。

适用对象 店铺运营、实施人员、后端开发、运维配置人员。
适用页面 “Amazon 店铺中心 / 店铺管理”页面中的新增店铺、去授权、测试连接、立即拉单。
当前内置站点 US（ATVPDKIKX0DER）、CA（A2EUQ1WTGCTBG2）、MX（A1AM78C64UM0Y8）。
授权有效关键点 授权回调必须命中系统配置的回调地址；授权 state 有效期为 20 分钟，超时需要重新发起授权。

1. 授权流程概览

  1. 运维先在系统配置中填写 Amazon 应用参数、LWA 参数、AWS 参数、回调地址和加密密钥。
  2. 在“店铺管理”页面新增店铺，至少填写店铺名称、区域、启用站点，保存记录。
  3. 点击“去授权”，系统会根据店铺所属区域跳转到对应 Seller Central 授权页。
  4. 卖家在 Amazon 页面确认授权后，Amazon 会回调系统配置的 `oauth-redirect-uri`。
  5. 系统使用回调中的 `spapi_oauth_code` 换取 `refresh_token`，并加密保存到数据库。
  6. 授权成功后，页面中的授权状态会变为“已授权”。建议立即执行“测试连接”。
  7. 测试连接通过后，可点击“立即拉单”验证订单接口和站点配置是否可用。
标准判定：授权成功后，至少应满足“授权状态 = 已授权”且“测试连接返回可访问站点”。

2. 授权前必备配置

以下配置位于服务端配置文件的 `amazon` 节点内，缺一项都可能导致授权发起失败、回调失败或接口验签失败。

配置项 是否必填 用途说明
`application-id` 是 用于拼装 Seller Central 授权链接；未配置时无法发起“去授权”。
`lwa-client-id` 是 用于将授权码换成 refresh token，以及后续 refresh token 换 access token。
`lwa-client-secret` 是 与 `lwa-client-id` 成对使用；未配置时 LWA 换 token 会失败。
`aws-access-key-id` 是 请求 SP-API 时参与 AWS SigV4 签名。
`aws-secret-access-key` 是 与 `aws-access-key-id` 配套；缺失时接口请求会直接报错。
`aws-role-arn` 否 当前代码中已预留字段，但当前流程未直接使用。
`oauth-redirect-uri` 是 Amazon 授权完成后的回调地址，必须与 Amazon 开发者后台登记值完全一致。
`encryption-key` 强烈建议填写 用于加密保存 refresh token。若未配置，会回退使用 `jwt.signing-key`；生产环境建议单独配置。
`auto-sync-orders` 否 控制是否启用自动订单同步任务。
`order-sync-spec` 否 自动同步订单的定时表达式。
amazon: application-id: "amzn1.sellerapps.app.xxxxx" lwa-client-id: "amzn1.application-oa2-client.xxxxx" lwa-client-secret: "your-secret" aws-access-key-id: "AKIAXXXXX" aws-secret-access-key: "xxxxx" aws-role-arn: "" oauth-redirect-uri: "https://your-domain.com/amazonStore/authCallback" encryption-key: "replace-with-a-strong-secret" auto-sync-orders: true order-sync-spec: "0 0 * * * *"
`oauth-redirect-uri` 必须与 Amazon 后台登记值完全一致，包括协议、域名、路径、端口和大小写。只要有一处不一致，授权回调就可能失败。

3. 回调地址写法说明

系统公开授权回调接口为：

GET {系统域名}{router-prefix}/amazonStore/authCallback

说明如下：

  • 如果系统配置 `system.router-prefix` 为空，则回调地址通常是 `https://your-domain.com/amazonStore/authCallback`。
  • 如果系统配置 `system.router-prefix` 为 `/api`，则回调地址通常是 `https://your-domain.com/api/amazonStore/authCallback`。
  • Amazon 回调会携带 `state`、`selling_partner_id`、`spapi_oauth_code` 等参数。
当前代码中“去授权”会先生成一个随机 `state`，并写入店铺记录中，20 分钟内有效。回调时系统会按这个 `state` 找到对应店铺并完成 token 入库。

4. 店铺管理页面字段说明

字段 说明 建议
店铺名称 系统内识别用名称，必填。 建议用“品牌 + 站点 + 店铺简称”命名。
区域 用于决定授权跳转域名和 SP-API 区域端点。当前支持 `NA`、`EU`、`FE`。 北美站选 `NA`，欧洲站选 `EU`，远东站选 `FE`。
Seller ID 卖家店铺标识，可选。 如已知可提前填写，不知可留空。
SP 卖家ID Selling Partner ID，可选，授权回调可自动回填。 通常授权完成后由系统写入更稳妥。
启用站点 决定测试连接展示的可用站点，以及订单同步请求的 marketplaceIds。 至少选择 1 个；未选择时无法拉单。
Refresh Token 可手动粘贴。只要保存时该字段非空，系统会直接视为“已授权”并加密存储。 优先走标准授权流程，手工 token 仅用于迁移或应急。
启用 决定该店铺是否参与启用店铺列表与自动同步流程。 正式启用前先完成测试连接。

5. 标准授权操作步骤

步骤一：新增店铺

  1. 进入“店铺管理”。
  2. 点击“新增店铺”。
  3. 填写店铺名称、区域、启用站点；Seller ID 和 SP 卖家ID可先留空。
  4. 保存。

步骤二：发起授权

  1. 在对应店铺行点击“去授权”。
  2. 系统会调用授权发起接口并返回 `authorizeUrl`。
  3. 浏览器新开窗口进入 Amazon Seller Central 授权页。

区域与 Seller Central 对应关系：

区域 Seller Central 域名
NA `https://sellercentral.amazon.com`
EU `https://sellercentral.amazon.co.uk`
FE `https://sellercentral.amazon.co.jp`

步骤三：Amazon 回调并入库 token

  1. 卖家在 Amazon 页面同意授权。
  2. Amazon 将浏览器重定向到配置好的 `oauth-redirect-uri`。
  3. 系统根据 `state` 找到对应店铺，校验是否过期。
  4. 系统用 `spapi_oauth_code` 向 Amazon LWA 换取 `refresh_token`。
  5. 系统加密保存 refresh token，并把授权状态更新为“已授权”。
成功回调后，浏览器会看到“Amazon 店铺授权成功，店铺：xxx，可关闭此窗口。”之类的提示。

6. 手动导入 Refresh Token 说明

如果已有可用的 refresh token，也可以不走 Amazon 页面授权，直接在新增/编辑店铺弹窗中填写 `Refresh Token` 后保存。

  1. 打开新增或编辑店铺弹窗。
  2. 将 refresh token 粘贴到“Refresh Token”文本框。
  3. 点击保存。
  4. 系统会立即加密保存 token，并把授权状态置为“已授权”。
手工导入 token 仅代表系统本地已保存凭证，不代表 Amazon 接口一定可用。保存后仍必须执行“测试连接”。

7. 授权后验证与拉单逻辑

测试连接

  • 页面点击“测试连接”后，系统会调用 SP-API 的卖家站点参与接口。
  • 调用成功时，页面会提示“连接成功，可访问站点：...”。
  • 调用失败时，系统会把错误写入店铺的 `last_error` 字段，便于排查。

立即拉单

  • “立即拉单”仅针对当前店铺执行一次订单同步。
  • 同步时会读取“启用站点”里的 marketplaceId 列表。
  • 首次同步默认拉取最近 24 小时订单；如果店铺之前同步过，则从“上次同步时间 - 10 分钟”开始补抓。
  • 同步成功后会更新“最后同步”时间，并写入同步订单数。
如果启用站点为空，即使授权成功，“立即拉单”也会失败，因为订单接口请求缺少 marketplaceIds。

8. 常见问题与排查建议

现象 常见原因 处理建议
点击“去授权”直接报错 `application-id` 或 `oauth-redirect-uri` 未配置 检查服务端 `amazon` 配置并重启服务。
授权完成后提示 state 过期 授权页面停留时间过长，超过 20 分钟 回到系统重新点击“去授权”。
回调后无法换取 token `lwa-client-id`、`lwa-client-secret` 错误，或回调地址与 Amazon 后台不一致 核对 LWA 参数和 redirect URI。
测试连接失败 refresh token 无效、AWS 签名参数错误、区域选错、网络无法访问 Amazon 优先重新授权，再检查 AWS 和区域配置。
重新部署后原 token 失效 `encryption-key` 被更换，导致旧 token 无法解密 保持加密密钥稳定；如已变更，只能重新授权或重新导入 token。
立即拉单失败 店铺未授权、启用站点为空、订单接口无权限或 Amazon 返回错误 先测试连接，再检查站点和订单 API 权限。

9. 安全与运维建议

  • 生产环境必须单独配置强随机 `amazon.encryption-key`，不要长期依赖默认值或仅依赖 JWT 签名密钥。
  • 授权使用的回调地址应为 HTTPS 公网地址，并在 Amazon 开发者后台同步登记。
  • 不要在前端页面、日志或聊天工具中明文传播 refresh token。
  • 若店铺停用或更换授权主体，建议删除旧授权并重新发起授权，避免凭证混用。
  • 授权完成后至少执行一次“测试连接”和一次“立即拉单”，再交给业务正式使用。
